# CloverGo

[English](README.en.md) | 简体中文

当前版本：**0.2.0** · MIT · 实验性版本

**把个人资料变成有出处的知识，再用于问答与公众号创作。**

CloverGo 把你反复阅读的资料（笔记、对话导出、文章）提炼成一条条可复用的知识，每条都绑定一段逐字摘自原文的出处。在这个知识库之上，它提供：

- **只读 Agent**：逐步检索、阅读知识库，校验回复中的知识引用编号；
- **带引用问答**；
- **公众号草稿**——长图文文章与图文帖（小绿书）——可以直接推送到公众号**草稿箱**。

整个程序是一个 Go 可执行文件、一个 SQLite 数据库和一个资料目录，React 界面内嵌在程序里，只允许绑定本机回环地址，默认 `127.0.0.1:8088`。运行时无需 Node、Docker 或单独部署数据库。界面默认中文，可切换英文。

适合希望复用笔记、文章和对话导出的个人创作者与开发者。当前为实验性版本，使用用户自有的火山方舟账号，模型调用按账号实际计费。**本机存储不等于离线 AI：总结、提炼、问答和创作会把相应内容发送到方舟。**

> **AI 编程项目。** CloverGo 的设计、代码、文档和评审由 **TraeWork**、**Claude Opus**、**GPT** 作为结对程序员参与完成，遵循 [AGENTS.md](AGENTS.md) 中的约束。这份文件是人和 AI 在本仓库协作的核心规则，细节见 [docs/BACKEND.md](docs/BACKEND.md) 与 [docs/FRONTEND.md](docs/FRONTEND.md)。

```text
资料（.md/.txt/.docx、粘贴文本，或扫描文件夹）
  → 整篇总结后只归档，不自动提炼（资料不一定是知识，可能只是存档）
  → 在资料列表显式「提炼」→ 单次提炼 → 出处必须是原文中连续、位置可复算的一段
  → 已确认知识（版本、已读/使用次数、向量）
  → 可选手动向量化：资料摘要 / 知识标题+正文
  → 检索：关键词 FTS + 语义向量，RRF 融合
       ├─ Agent      有步数上限的工具调用循环，只读工具，带引用回复
       ├─ 问答        一次性带引用回答
       └─ 公众号草稿：长文章或图文帖（可从知识或资料原文出发）
            → 复制 / 导出 ZIP / 推送到草稿箱；未上传的图片位在推送时使用本地标题卡片
  → 每次模型调用都是一个 Run：步骤、耗时、token、Prompt 版本
```

## 现状

| 能力 | 状态 | 说明 |
| --- | --- | --- |
| 文件夹扫描导入 | ✅ 已实测 | 登记本机文件夹，只读扫描（不跟随符号链接），出报告：新增 / 已变更 / 未变化 / 库中已有 / 已消失 / 被跳过（超过 `MAX_UPLOAD_MB`、转换后超过 `MAX_DOCUMENT_RUNES`、为空、非 UTF-8、docx 损坏，均列明原因）。只处理 `.md/.markdown/.txt/.docx`；`.docx` 转纯文本后存储的就是这份文本。由你勾选文件，再逐个导入（总结）；变更的文件成为同一来源的新版本 |
| 资料导入与提炼 | ✅ 已实测 | UTF-8 `.md/.markdown/.txt` 与 `.docx` 批量或粘贴；导入只总结并归档，不自动提炼——资料不一定是知识，可能只是存档；提炼是资料列表里的显式操作（整篇一次调用），创作也可以直接用资料原文；同名资料再导入生成新版本，旧出处退出检索 |
| 出处校验 | ✅ 已实测 | 每条知识引用原文连续片段，偏移可复算；提炼输出的知识类型来自固定分类，所有者编辑单条知识时可输入自定义分类 |
| 混合检索 | ✅ 已实测，有效果限制 | FTS5 关键词 + `doubao-embedding-vision` 向量（知识**与资料**都嵌），RRF 融合；命中的资料会把其提炼出的知识提权；无当前向量的知识仅参与关键词检索。本次中文查询命中，两个英文查询未命中，不承诺跨语言召回效果 |
| Agent | ✅ 已实测 | 最多 8 轮模型调用；工具 `search_knowledge`（可选 `topic` 限定主题）、`get_knowledge`、`get_document`、`list_documents`、`library_overview`；`[K<id>]` 引用必须是本次工具真实返回过的知识（违规时纠正重试一次，仍违规则失败）；支持多轮；按用户语言回复 |
| 带引用问答 | ✅ 已实测 | 使用检索到的知识作为上下文，返回可回看出处的引用；引用校验不保证回答中的每个判断都正确 |
| 公众号文章草稿 | ✅ 已实测 | 引言 + 2–5 章 + 结尾，另有标题、摘要、封面配图提示词、标签；正文目标 1000 字左右、最多 2000 字；只写一段创作灵感、只指定来源（知识点或资料原文），或随机一条知识点都能写。来源只作为写作输入，不在文章里引用。生成在后台进行：请求立即返回 `status: running`，模型输出不合法时自动重试一次，写好后列表自动刷新；每篇文章同时落盘 `data/drafts/<id>-<标题>.md`，并可在独立详情页查看、修改、删除、推送 |
| 公众号图文帖 | ✅ 已实测 | 短正文 + 1–3 张图（默认 1）。每张图是一条提示词；推送时每个位置可上传自己的图（JPEG/PNG/GIF，自动等比缩放到 1080×1440 以内并转 JPEG），未上传的才把标题排成 SVG 卡片（只有标题，不印提示词；草稿详情页的图片位会预览这张卡片）并在本机转成 PNG（ImageMagick、librsvg、Inkscape，或带 SVG 解码器的 ffmpeg），不调用图片模型；以 `article_type: newspic` 推送，第一张图就是封面。有未上传位置且本机没有 SVG 转 PNG 工具时拒绝推送，因为图片就是内容本身 |
| 推送到公众号草稿箱 | ⚠️ 已实现，部分验证 | 长文章：`stable_token` → 上传封面 → `draft/add`；图文帖：逐张渲染并上传图片 → `draft/add`（`newspic`）。成功推送需要你自己的公众号凭据，在「配置 → 接口配置」里填写。同一页可填可选 SOCKS5 代理，本地部署因此有固定出口 IP，家宽 IP 变化时不必反复改白名单 |
| 中英双语界面 | ✅ | 默认中文，可切英文，偏好存在 `localStorage` |
| 本机安全闸门 | ✅ 已实测 | 拒绝非本机 Host、跨站请求、非 JSON 写请求 |
| 全局密码（锁屏） | ✅ 已实测 | 可选，在「设置 → 安全」里设置。密码以加盐 PBKDF2 哈希存在 SQLite（`app_lock`），浏览器在 `localStorage` 里保存解锁令牌；服务端对除 `auth/status`、`auth/unlock` 外的所有 `/api/v1/*` 请求强制校验（请求头 `X-CloverGo-Token`），改密、删除密码或重启服务都会使旧令牌失效（令牌 30 天过期）。这是本机锁屏，不是多用户账号——能读数据目录的人仍可读到数据；连续输错 5 次锁定 30 秒（计数在内存，重启清零）；仅 `/health/live`、`/health/ready` 与静态界面不受保护 |

表中的“已实测”包含历史验收，最新范围与限制见 [开源验收记录](docs/RELEASE-CHECK.md)。2026-10-18 的历史样本：一个 Agent 问题检索 2 次、9.4 秒；一次多轮追问用了 4 轮模型调用、6 次工具调用、1.83 万 token；一个无关问题检索后回答“知识库没有”。这些是样本结果，不是速度、成本或准确率承诺。

**明确未实现**（不得宣称已支持）：定时/自动发布、公众号以外平台的发布、发布状态查询、AI 生成图片（图片是本地排版的标题 SVG 卡片；本机没有 SVG 光栅化工具时长文章会丢掉配图）、联网搜索、PDF/OCR、旧版 DOC、Excel/PPT 等其他 Office 格式、账号与多租户、局域网/公网部署，以及任何会写数据、执行命令或打开 URL 的 Agent 工具。DOCX 仅提取文本，不保留版式、图片或表格布局。

## 数据与隐私

- 原始资料快照、知识、草稿、运行记录和问答历史保存在本机；运行记录可能包含输入和模型输出，不只是耗时与 token 元数据。锁屏不会加密数据库或资料文件。
- 总结与提炼发送整篇资料；问答、Agent 和草稿生成发送问题、必要的对话与所选资料/检索上下文；启用向量化后，还会发送资料摘要、知识正文与检索问题。请按资料的授权范围选择导入内容。
- 只有主动使用公众号接口时才向微信发送账号凭据、草稿与图片；“推送并发布”是显式操作，返回发布任务编号不代表已经发布成功。
- 方舟 Key 通过进程环境或忽略的 `.env` 配置；公众号凭据及代理配置保存在本机 SQLite。设置接口不回传 AppSecret，并遮蔽代理 URL 的用户名和密码；原样保存遮蔽地址保留原配置，清空地址删除代理，填写新地址替换代理。
- 分享项目时只分享源码或构建好的程序，不分享 `.env`、`data/`、`.local/`、数据库、日志、浏览器存储或私人演示截图。

出处校验确认的是“引用片段确实来自原文”；Agent 引用编号校验确认的是“该知识由本轮工具返回过”。它们不证明原文真实，也不能消除模型幻觉，生成内容仍需人工核对。

## 快速开始

需要 Go 1.26+。只有重新构建界面时才需要 Node 22+。

```powershell
Copy-Item .env.example .env
notepad .env        # 填写 ARK_API_KEY，确认 ARK_MODEL 在你的账号可用
go run .            # http://127.0.0.1:8088
```

| 变量 | 作用 |
| --- | --- |
| `ARK_API_KEY`、`ARK_MODEL`、`ARK_BASE_URL` | 火山方舟对话模型（只接受官方 `volces.com` HTTPS 地址） |
| `ARK_EMBEDDING_MODEL`、`ARK_EMBEDDING_DIMENSIONS` | 可选，语义检索；留空只用关键词 |
| `AUTO_PUBLISH_MIN_CONFIDENCE` | 提炼时模型自评置信度低于该值（默认 `0.72`）的知识会被丢弃 |
| `WECHAT_APP_ID`、`WECHAT_APP_SECRET` | 可选初始值，用于推送到公众号草稿箱；在配置页保存后以数据库中的值为准。推送的出口地址（本机公网 IP，配置了代理时为代理出口 IP）必须在公众号的 API IP 白名单里 |
| `WECHAT_AUTHOR`、`WECHAT_THUMB_MEDIA_ID` | 可选初始值：作者名与默认封面的 `media_id` |
| `WECHAT_PROXY_URL` | 可选初始值：推送用的 `socks5://user:password@host:port` 代理 |

方舟 Key 只从进程环境或 Git 忽略的 `.env` 读取，不会写进 SQLite、日志、导出包或界面。公众号 AppID/AppSecret 由所有者在「配置 → 接口配置」填写，存进本机 SQLite（`wechat_settings`），不会写入日志或导出包；接口不回传 AppSecret（只返回 `app_secret_set`），保存时留空即保留原值。同一页可填可选的 `socks5://user:password@host:port` 代理：推送从代理出口发出，公众号 IP 白名单填代理地址即可（白名单不能留空，`stable_token` 同样受限）。没有方舟 Key 时，需要模型的操作明确报 `ARK_NOT_CONFIGURED`，不会生成假结果。

推送说明：推送会让草稿进入公众号**草稿箱**；只有选择「推送并发布」（`?mode=publish`）才会再调用 `freepublish/submit` 提交发布（需要公众号具备发布权限，不查询异步发布结果）。长文章的配图会在推送时由本机渲染成标题卡片并插入正文；本机没有可用的 SVG 转 PNG 工具时，配图与提示词一并略去。图文帖每个图片位置都上传文件时无需该工具；存在未上传位置时需要工具生成标题卡片。发布前请检查图片。

前端开发：

```powershell
Set-Location frontend
npm ci
npm run dev         # 127.0.0.1:5173，/api 代理到 8088
npm run build       # 类型检查并输出到 ../web/dist（需提交，会内嵌进程序）
```

## Agent

`POST /api/v1/agent/chat`，请求体 `{"messages":[{"role":"user","content":"..."}]}`。对话保存在客户端，每轮完整发回（最多 20 条），服务端不保存会话；但每次回答会记入历史，可用 `GET /api/v1/agent/history` 分页回看。

- 模型在一组固定的只读工具里自己选择；工具走的是与界面相同的服务路径。
- 工具结果一律当作数据，不当作指令。
- 回复里引用了本次工具没有返回过的 ID 会被拒绝（`ARK_INVALID_RESPONSE`）；轮数用尽返回 `AGENT_STEP_LIMIT`。
- 每一轮、每次工具调用都在服务端记为 Run 事件（界面不再展示 Run）。

演进方向是**本地 Agent**：目前循环通过 OpenAI 兼容的对话接口调用方舟，循环、工具与校验本身与厂商无关。

接口与错误码表见 [README.en.md](README.en.md#api)。
